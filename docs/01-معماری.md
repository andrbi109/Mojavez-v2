# معماری سامانه 🏗️

## ۱. نمای کلی

سامانه بر پایهٔ **MVC دست‌نویس** با PHP 8 خالص پیاده‌سازی شده است؛ بدون فریم‌ورک، بدون
کامپوزر و بدون هیچ وابستگی خارجی. تنها دارایی سمت کلاینت، Bootstrap 5 RTL و فونت
وزیرمتن هستند که به‌صورت **محلی** در `public/assets` قرار دارند (با کلید `USE_CDN`
قابل تغییر به CDN).

```
مرورگر کاربر
    │  URL تمیز (mod_rewrite یا router.php در توسعه)
    ▼
public/index.php  ←── نقطهٔ ورود یگانه (Front Controller)
    │  • بارگذاری config / helper / jdf
    │  • ثبت AutoLoader
    │  • هدرهای امنیتی سراسری
    │  • مدیریت خطای کنترل‌نشده (APP_DEBUG)
    │  • تعریف مسیرها و dispatch
    ▼
core/Router.php ──► app/Controllers/* ──► app/Models/* ──► MySQL (PDO)
                          │
                          ├── app/Services/AutoCancelService
                          └── app/Views/* (رندر با layout)
```

## ۲. ساختار پوشه‌ها و مسئولیت‌ها

| مسیر | مسئولیت |
|---|---|
| `public/` | **document root** — تنها نقطهٔ قابل دسترسی وب. شامل `index.php`، `.htaccess`، `assets/` و `router.php` (فقط توسعه) |
| `config/` | `config.php` (ثابت‌ها)، `helper.php` (توابع تاریخ شمسی + `setting()` + `social_links()` + `icon()` — سیستم آیکون SVG)، `jdf.php` (تقویم جلالی)، `workflow.php` (قواعد انتقال نقش‌ها)، `statuses.php` (**مرجع مرکزی وضعیت‌ها**: ترتیب یکطرفه، رنگ، قابلیت تنظیم دستی، مشمول لغو خودکار) |
| `core/` | `Router`, `Database` (Singleton PDO), `Session` (CSRF + Rate Limit + تم)، `Validator`, `CsvExporter`, `PdfGenerator`, `AutoLoader` |
| `app/Controllers/` | کنترلرهای HTTP؛ ارث‌بری از `Controller` پایه (render/redirect/verifyCsrf/requireRole) |
| `app/Models/` | لایهٔ داده؛ هر مدل یک جدول + کوئری‌های Prepared |
| `app/Services/` | منطق بین‌لایه‌ای: `AutoCancelService` (لغو خودکار + اولویت‌بندی) |
| `app/Views/` | قالب‌ها: `layout.php` (عمومی)، `admin_layout.php` (پنل)، `layout_print.php` (چاپ) + نماهای صفحات |
| `uploads/` | فایل‌های کاربران — **خارج از public** با `.htaccess` محافظ (لایهٔ دوم) |
| `database/` | `schema.sql` (یکپارچه — شامل همهٔ جداول، روابط و بذر اولیه) |
| `tests/` | `smoke-test.sh` — آزمون سرتاسری (end-to-end) با curl |

## ۳. جریان یک درخواست (Request Lifecycle)

۱. Apache به‌واسطهٔ `public/.htaccess` همهٔ مسیرهای غیرفیزیکی را به `index.php` بازنویسی می‌کند
   (در توسعه، `router.php` همین نقش را برای سرور داخلی PHP بازی می‌کند).
۲. `index.php` ثابت‌های مسیر را تعریف، `AutoLoader` را ثبت و `Session::start()` را صدا می‌کند.
۳. `Router::dispatch()` متد و URI را با الگوهای ثبت‌شده تطبیق می‌دهد؛ پارامترهای `{id}`
   به‌صورت named capture استخراج و به اکشن کنترلر پاس داده می‌شوند.
۴. کنترلر: بررسی احراز هویت/نقش → اعتبارسنجی CSRF (در POST) → اعتبارسنجی داده با
   `Validator` → تعامل با مدل‌ها → ذخیرهٔ پیام‌ها در Session (الگوی PRG) → رندر نما یا redirect.
۵. نما داخل بافر خروجی رندر شده و درون layout مربوطه قرار می‌گیرد.

## ۴. الگوهای طراحی به‌کار رفته

| الگو | محل استفاده |
|---|---|
| **Singleton** | `Database::getInstance()` — یک اتصال PDO در کل چرخهٔ درخواست |
| **Front Controller** | `public/index.php` |
| **Post/Redirect/Get** | همهٔ فرم‌ها؛ خطاها و داده‌های بازگشتی در Session (جلوگیری از ارسال مجدد فرم) |
| **Autoloader (SPL)** | `core/AutoLoader.php` — جستجوی کلاس در `core/`, `Controllers/`, `Models/`, `Services/` |
| **Repository-مانند** | مدل‌ها فقط کوئری می‌دانند، نه منطق تجاری |
| **Service** | `AutoCancelService` — منطق زمان‌محور لغو/اولویت جدا از کنترلرها |
| **Workflow/State Machine** | `config/workflow.php` + ترتیب یکطرفهٔ وضعیت‌ها در `AdminController::changeStatus` |

## ۵. مکانیزم‌های زمان‌محور (بدون cron)

سرورهای اشتراکی ممکن است cron در اختیار نگذارند؛ بنابراین هر دو وظیفهٔ زمان‌محور
به‌صورت **رویداد-محور (Event-driven)** در نقاط ورودی پربازدید اجرا می‌شوند:

```php
AutoCancelService::cancelExpired();    // لغو درخواست‌های > AUTO_CANCEL_DAYS روز
AutoCancelService::updatePriorities(); // پرچم ⭐ برای ثبت‌نام‌های > PRIORITY_DAYS روز
```

نقاط فراخوانی: داشبورد مدیر، فهرست درخواست‌ها، صفحهٔ پیگیری کاربر، و
`GET /check-cancel` (اجرای دستی/خودکار بیرونی).

هر دو عملیات **Idempotent** هستند: شرط `current_status != 'لغو'` و `priority = 0`
از تکرار بیهوده جلوگیری می‌کند.

## ۶. ویزارد ثبت‌نام (چگونه کار می‌کند)

- دادهٔ هر مرحله پس از اعتبارسنجی در `$_SESSION['registration']['stepN']` ذخیره می‌شود.
- مراحل بعدی بدون وجود مراحل قبل قابل دسترسی نیستند (بررسی در GET و POST).
- در مرحلهٔ ۴ همهٔ داده‌ها در یک **تراکنش اتمی** PDO درج می‌شوند:
  `applicants` ← `job_details` ← `property_details` ← `documents` ← `status_log`.
- کد رهگیری با `random_bytes` تولید و یکتایی آن در جدول بررسی می‌شود.
- پس از موفقیت، دادهٔ ویزارد از سشن پاک می‌شود (`clearRegistration`).

## ۷. لایهٔ نمایش و قالب‌ها

| قالب | کاربرد | ویژگی |
|---|---|---|
| `layout.php` | صفحات عمومی (خانه، ثبت‌نام، پیگیری) | نوار بالای واکنش‌گرا با همبرگر، فوتر، fallback CDN/محلی |
| `admin_layout.php` | پنل مدیریت | سایدبار تیره ثابت (دسکتاپ) / Off-canvas (موبایل)، منوی نقش‌محور، نشانگر درخواست‌های کد پستی |
| `layout_print.php` | پروندهٔ چاپی | نوار ابزار شناور چاپ، `@page A4`، مدیریت `page-break` |

## ۸. قراردادهای کدنویسی

- همهٔ کامنت‌ها و پیام‌های کاربر **فارسی** هستند.
- خروجی‌گیری در نماها فقط با `htmlspecialchars()` (یا `e()` در ReportController).
- کوئری‌ها فقط Prepared Statements؛ هیچ الحاق مستقیم ورودی کاربر به SQL وجود ندارد
  (ستون‌های `ORDER BY`/`GROUP BY` از فهرست سفید کد انتخاب می‌شوند).
- تاریخ‌های میلادی در پایگاه داده و نمایش شمسی در رابط کاربری (jdf.php).

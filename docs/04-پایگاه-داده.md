# پایگاه داده 🗄️

نام پایگاه داده: `handicraft_license` — کدگذاری `utf8mb4` با `utf8mb4_unicode_ci`
(پشتیبانی کامل فارسی و ایموجی). موتور جداول: `InnoDB` (پشتیبانی تراکنش و کلید خارجی).

کد کامل پایگاه داده در یک فایل واحد `database/schema.sql` قرار دارد. نصب با یک دستور:

```bash
mysql -u root -p < database/schema.sql
```

این فایل با `IF NOT EXISTS` و `ON DUPLICATE KEY UPDATE` طراحی شده است؛ اجرای مجدد آن
در نصب‌های موجود، داده‌ها را حذف نمی‌کند.

---

## ۱. نمودار روابط (ERD متنی)

```
                    ┌─────────────┐
                    │    users    │  مدیران/کارشناسان پنل
                    │ role, ...   │◄──────────────┐
                    └─────────────┘               │ reviewed_by (SET NULL)
                          ▲                       │
                          │ (ممیزی غیرمستقیم)     │
                    ┌─────┴──────────────┐   ┌────┴──────────────────┐
                    │     applicants     │1:N│   postal_code_changes │
                    │ tracking_code (UQ) │◄──┤   status, reviewed_at │
                    │ person_id (FK)     │   └───────────────────────┘
                    │ current_status     │1:N┌───────────────────────┐
                    │ priority ⭐        │◄──┤      status_log       │
                    └──┬─────┬─────┬─────┘   └───────────────────────┘
                  1:1  │     │     │  1:N   ┌───────────────────────┐
        ┌──────────────┘     │     └───────►│       documents       │
        ▼                    ▼              │  doc_type, file_path  │
┌───────────────┐   ┌──────────────────┐    └───────────────────────┘
│  job_details  │   │ property_details │
│ license_title │   │ province/city/…  │
│ training_meth.│   │ electricity_bill │
└───────────────┘   └──────────────────┘
```

همهٔ روابط فرع با `ON DELETE CASCADE` — حذف یک پرونده، تمام دادهٔ وابسته را پاک می‌کند.

### ۲.۳ `job_details` — اطلاعات شغلی (۱:۱)
`license_title VARCHAR(100)` • `experience_months INT` •
`training_method ENUM('در خانه','استاد شاگردی','کارگاهی')` •
`UNIQUE(applicant_id)` — تضمین رابطهٔ یک‌به‌یک در سطح دیتابیس.

### ۲.۴ `property_details` — اطلاعات ملک (۱:۱)
`ownership_status ENUM('شخص','مستأجر','سرپرست')` • استان/شهرستان/شهر (اجباری) •
بخش/دهستان/روستا (اختیاری) • `electricity_bill_id VARCHAR(20)` •
`address_street`, `address_alley`, `address_plaque` • `UNIQUE(applicant_id)`.

### ۲.۵ `documents` — مدارک (۱:N)
`doc_type`: یکی از
`national_card | birth_cert | ownership_doc | lease_agreement | supervisor_doc | vocational_cert | education_degree | product_photos | optional | dynamic`
• `file_name` (نام تصادفی ذخیره‌شده) • `original_name` • `file_path` (نسبت به `uploads/`
با زیرپوشهٔ `Y/m`) • `uploaded_at`.

### ۲.۶ `status_log` — تایم‌لاین رویدادها (۱:N)
`status_name` (هر وضعیت اصلی یا رویدادهای ویژه: «درخواست تغییر کد پستی»،
«مشاهده و چاپ پرونده»، «تأیید/رد تغییر کد پستی»، «ویرایش اطلاعات توسط مدیر»،
«افزودن مدرک توسط مدیر») • `description` • `created_at` (ایندکس‌شده —
مبنای محاسبهٔ لغو خودکار).

### ۲.۷ `postal_code_changes` — درخواست‌های تغییر کد پستی (۱:N)
| ستون | نوع | توضیح |
|---|---|---|
| old_postal_code / new_postal_code | CHAR(10) | مقدار فعلی و درخواستی |
| status | ENUM('در انتظار','تأیید شده','رد شده') | |
| reviewed_by | INT FK→users (SET NULL) | ممیزی بررسی‌کننده |
| reviewed_at | DATETIME | |
| reject_reason | VARCHAR(255) | |
| requested_at | DATETIME | |

### ۲.۸ `settings` — تنظیمات سامانه
کلید/مقدار ساده: `setting_key` (PK) • `setting_value TEXT` • `updated_at`.
کلیدهای فعلی: `site_name`, `owner_name`, `owner_username`, `social_eitaa`,
`social_rubika`, `social_bale`, `success_message_template`, `about_title`, `about_content`,
`owner_image`, `registration_fee_amount`, `license_reissue_fee_amount`.

### ۲.۹ `form_fields` — تعریف فیلدهای فرم
`step` (۱..۴) • `wizard_step_id` FK→wizard_steps • `service_type_id` FK→service_types •
`field_key UNIQUE` • `label` • `field_type`
(text/number/textarea/select/radio/checkbox/date_jalali/file) • `options` (گزینه‌ها، هر خط یکی)
• `is_required` • `is_system` (داخلی — حذف‌ناپذیر) • `is_active` (حذف از فرم) •
`validation_json` (`{min,max,maxlength,pattern}`) • `placeholder` • `help_text` • `sort_order`.
ایندکس: `idx_step_active(step, is_active, sort_order)`.

### ۲.۱۰ `applicant_field_values` — مقادیر فیلدهای پویا
`applicant_id` FK(CASCADE) • `field_id` FK→form_fields(CASCADE) • `field_value TEXT` •
`UNIQUE(applicant_id, field_id)`. مقادیر فایلی به شکل `doc:{document_id}` ذخیره می‌شوند
(ارجاع به جدول documents با `doc_type='dynamic'`).

### ۲.۱۱ `license_titles` — رشته‌های مجوز
`category` (دسته/گروه) • `title UNIQUE` • `is_active` • `sort_order`.
~۹۰ رشته در ۱۲ دسته بر پایهٔ طبقه‌بندی فرهنگستان هنر بذر شده و از پنل مدیریت
(مسیر `/admin/license-titles`) قابل CRUD است. رشتهٔ در حال استفاده در پرونده‌ها
حذف نمی‌شود (فقط غیرفعال) تا یکپارچگی داده حفظ گردد.

### ۲.۱۲ وضعیت‌های پرونده (۱۴ وضعیت)
`applicants.current_status` اکنون ۱۴ مقدار دارد:
پیش‌نویس، تکمیل اطلاعات، احراز نشانی، **بررسی کارشناسی رشته**، ثبت درخواست صدور،
بارگذاری مدارک به سازمان، **درخواست اصلاح مدارک**، تأیید اولیه، **تأیید نهایی**،
صدور مجوز، **تحویل مجوز**، مشاهده و چاپ، **رد درخواست**، لغو.
مرجع مرکزی ترتیب/رنگ/قواعد: `config/statuses.php`.

### ۲.۱۳ `persons` — لنگر هویت (چندمجوزی)
`national_code CHAR(10) UNIQUE` • `first_name` • `last_name` • `father_name` •
`birth_date` • `mobile` • `postal_code` • `person_type ENUM('حقیقی','حقوقی')` •
فیلدهای حقوقی: `company_name`, `company_national_id CHAR(11)`, `reg_number`, `reg_date`,
`company_type`, `economic_code`.

### ۲.۱۴ `wizard_steps` — مراحل ویزارد پویا
`view_key` (برای مراحل سیستمی step1..step4؛ سفارشی‌ها NULL) • `title` • `description` •
`icon` • `service_type_id` FK • `is_system` • `is_active` • `sort_order` (مدارک = ۱۰۰۰).

### ۲.۱۵ `service_types` — انواع خدمات
`title UNIQUE` • `authority` • `description` • `is_active` • `sort_order`.
۵ سرویس بذر: صنایع دستی، مشاغل خانگی مستقل، مشاغل خانگی پشتیبان، گردشگری، هنری.

### ۲.۱۶ `payment_channels` و `payments` — گردش پرداخت
`payment_channels`: کانال‌های پرداخت (کارت/حساب/درگاه) با `title`, `channel_type`, `account_info`.
`payments`: رسیدهای پرداخت متقاضیان با `purpose` (ثبت‌نام / دریافت مجدد مجوز)، `amount`,
`reference_code`, `paid_at`, `receipt_document_id`, `status`, `linked_request_id`.

### ۲.۱۷ `license_files` و `license_access_requests` — تصویر مجوز
`license_files`: تصویر مجوز صادرشدهٔ هر پرونده (UNIQUE applicant_id) + `download_count`
(قاعدهٔ یک‌بار دریافت).
`license_access_requests`: درخواست‌های دسترسی به تصویر مجوز؛ `access_token` ۶۴ کاراکتری +
`expires_at` (۷۲ ساعت) + وضعیت (در انتظار/تأیید/رد/در انتظار پرداخت/منقضی).

### ۲.۱۸ `sms_templates` و `user_sms_entries` — پیامک وضعیت
`sms_templates`: الگوهای پیامک با `title`, `sample_text`, `target_status`, `requires_code`.
`user_sms_entries`: پیامک‌های ثبت‌شده توسط متقاضی → پس از تأیید مدیر، ارتقای وضعیت
(مسیر یکطرفه رعایت می‌شود).

### ۲.۱۹ `applicant_revisions` — چرخهٔ بازبینی پرونده
`payload` JSON کامل (هویت/شغل/ملک/فیلدهای پویا/مدارک جدید) • `note` • `status` •
`reviewed_by` • `reviewed_at` • `reject_reason`.

### ۲.۲۰ `identity_checks` — لاگ احراز هویت
`national_code` • `ip` • `success` • `created_at`.
برای قفل تصاعدی: ۵ خطا در ۱۰ دقیقه → قفل موقت.

## ۳. مکانیزم‌های زمانی در سطح کوئری

**لغو خودکار** (`Applicant::findExpiredApplications`):
```sql
SELECT a.* FROM applicants a
JOIN status_log sl ON sl.applicant_id = a.id
WHERE sl.status_name = 'ثبت درخواست صدور'
  AND a.current_status IN ('پیش‌نویس','تکمیل اطلاعات','احراز نشانی',
                           'ثبت درخواست صدور','بارگذاری مدارک به سازمان','تأیید اولیه')
  AND sl.created_at < DATE_SUB(NOW(), INTERVAL 14 DAY)
```

**اولویت‌بندی خودکار** (`AutoCancelService::updatePriorities`):
```sql
UPDATE applicants SET priority = 1
WHERE priority = 0
  AND TIMESTAMPDIFF(SECOND, registration_started_at, registration_completed_at) > 1036800
```

## ۴. نکات نگهداری

- **یکتایی موبایل:** در سطح `persons` یکتا است. یک شخص می‌تواند چند پرونده داشته باشد.
- **بک‌اپ:** `mysqldump handicraft_license` + آرشیو `uploads/` — هر دو با هم بازیابی شوند
  چون `documents.file_path` به ساختار پوشه وابسته است.
- **کاراکتر ZWNJ:** نام‌های فارسی با نیم‌فاصله ذخیره می‌شوند؛ هنگام جستجوی LIKE
  به تفاوت «می‌شود/میشود» دقت کنید (در صورت نیاز تابع نرمال‌سازی اضافه شود).
- **اعتبارسنجی‌ها:** رقم کنترل کد ملی ۱۰ رقمی و شناسهٔ ملی ۱۱ رقمی حقوقی
  (الگوریتم‌های استاندارد در `core/Validator.php`).

## ۵. ساختار کامل فایل‌ها

همهٔ جداول، روابط، ایندکس‌ها و دادهٔ بذر اولیه در یک فایل واحد قرار دارند:

```
database/
└── schema.sql    # اسکیمای کامل پایگاه داده (یکپارچه)
```

اجرای مجدد schema.sql به‌دلیل استفاده از `IF NOT EXISTS` و `ON DUPLICATE KEY UPDATE`
امن است و داده‌های موجود را حذف نمی‌کند.

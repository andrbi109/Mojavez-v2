# راهنمای استقرار 🚀

## ۱. محیط توسعه (سرور داخلی PHP — بدون Apache)

مناسب توسعه و تست سریع روی هر سیستمی با PHP 8:

```bash
./dev-server.sh start     # اجرا روی http://127.0.0.1:8000
./dev-server.sh status    # وضعیت
./dev-server.sh logs 100  # مشاهدهٔ لاگ
./dev-server.sh stop      # توقف
# یا مستقیم:
php -S localhost:8000 -t public public/router.php
```

`public/router.php` نقش `mod_rewrite` را شبیه‌سازی می‌کند: فایل‌های استاتیک واقعی
مستقیم سرو شده و بقیهٔ مسیرها به `index.php` می‌روند. **این فایل در تولید استفاده نمی‌شود.**

## ۲. XAMPP (ویندوز)

1. MariaDB و Apache را از کنترل پنل XAMPP اجرا کنید (`mod_rewrite` به‌صورت پیش‌فرض فعال است).
2. پوشهٔ پروژه را در `C:\xampp\htdocs\mojavez` کپی کنید.
3. در phpMyAdmin فایل‌های `database/schema.sql` و سپس `update-v0.0.2/3/4.sql` را Import کنید.
4. `config/config.php`:
   ```php
   define('DB_USER', 'root');
   define('DB_PASS', '');
   define('BASE_URL', '/mojavez/public/');   // ⚠️ در زیرپوشه
   ```
5. دسترسی: `http://localhost/mojavez/public/`

> **حالت تمیزتر (document root روی public):** در `httpd.conf` خط
> `DocumentRoot "C:/xampp/htdocs"` را به `DocumentRoot "C:/xampp/htdocs/mojavez/public"`
> تغییر دهید (و `<Directory>` متناظر را هم اصلاح کنید)؛ آنگاه `BASE_URL = '/'`.

## ۳. Laragon (ویندوز — توصیه‌شده برای لوکال)

Laragon به‌طور خودکار Virtual Host می‌سازد:
1. پروژه را در `C:\laragon\www\mojavez` قرار دهید → `http://mojavez.test`
2. برای ریشه‌شدن `public`: پروژه را به `C:\laragon\www\mojavez` برده و در
   `Apache/sites-enabled/auto.mojavez.test.conf` مسیر root را به
   `C:/laragon/www/mojavez/public` تغییر دهید؛ یا ساده‌تر `BASE_URL='/mojavez/public/'`.
3. دیتابیس را با Menu → MySQL → Import بسازید.

## ۴. سرور اشتراکی / cPanel (دامنهٔ اصلی)

### الف) آپلود
1. کل پروژه را در `public_html/mojavez-src/` آپلود کنید (یا بهتر: خارج از
   `public_html` مثل `~/mojavez-src/`).
2. محتویات `public/` باید document root دامنه (یا زیردامنه) باشد:
   - **حالت ایده‌آل:** document root ساب‌دامین را در cPanel روی `~/mojavez-src/public` تنظیم کنید.
   - **حالت جایگزین:** محتویات `public/` را داخل `public_html/` بریزید و بقیهٔ پوشه‌ها
     (app, core, config, uploads, database) را در `public_html/../mojavez-src/` نگهدارید؛
     سپس در `public_html/index.php` مسیر `dirname(__DIR__)` را به مسیر واقعی اصلاح کنید.

### ب) پیکربندی
```php
define('APP_DEBUG', false);          // ⚠️ در تولید
define('DB_HOST', 'localhost');      // طبق اطلاعات cPanel
define('DB_NAME', 'USER_mojavez');
define('DB_USER', 'USER_mojavez');
define('DB_PASS', 'رمز قوی ساخته‌شده در cPanel');
define('BASE_URL', '/');             // یا '/subdir/' برای زیرپوشه
define('USE_CDN', true);             // اختیاری — کاهش بار سرور
```

### ج) ساخت دیتابیس
1. در cPanel → MySQL Databases: ساخت دیتابیس و کاربر و افزودن کاربر با دسترسی ALL.
2. در phpMyAdmin: Import فایل‌های `schema.sql` و سه مهاجرت بعدی **به‌ترتیب**.

### د) مجوزها
```bash
chmod 755 uploads/          # خود پوشه
chmod 640 uploads/**        # فایل‌ها (کد به‌صورت خودکار 0640 می‌دهد)
```

### هـ) HTTPS (الزامی توصیه‌شده)
- فعال‌سازی AutoSSL/Let's Encrypt در cPanel.
- هدایت HTTP→HTTPS با افزودن به `public/.htaccess`:
  ```apache
  RewriteCond %{HTTPS} off
  RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
  ```
- کوکی `Secure` به‌صورت خودکار وقتی HTTPS تشخیص داده شود فعال می‌شود.

## ۵. بررسی پس از استقرار ✅

| بررسی | انتظار |
|---|---|
| `https://دامنه/` | صفحهٔ اصلی بدون خطا |
| `https://دامنه/admin/login` | فرم ورود؛ ورود با رمز تغییر یافته |
| `https://دامنه/uploads/.htaccess` | ۴۰۳/۴۰۴ (دسترسی مسدود) |
| `https://دامنه/config/config.php` | ۴۰۴ (خارج از document root) |
| ثبت‌نام کامل یک پروندهٔ آزمایشی + آپلود مدرک | کد رهگیری صادر شود |
| `/check-cancel` | `{"cancelled":0,...}` |
| هدرها (`curl -I`) | وجود `X-Frame-Options` و `nosniff` |

## ۶. رفع اشکال‌های رایج

| علامت | علت معمول | راه‌حل |
|---|---|---|
| همهٔ مسیرها ۴۰۴ | `mod_rewrite` خاموش یا `AllowOverride None` | فعال‌سازی `a2enmod rewrite` و `AllowOverride All` در `<Directory>` |
| خطای اتصال دیتابیس | نام کاربری/رمز/نام دیتابیس اشتباه | بررسی `config.php` با اطلاعات cPanel |
| آپلود ناموفق | `upload_max_filesize`/`post_max_size` کوچک | در `.htaccess` یا php.ini: `php_value upload_max_filesize 8M` و `post_max_size 12M` |
| صفحهٔ سفید | خطای PHP مخفی با `APP_DEBUG=false` | موقتاً `APP_DEBUG=true` یا بررسی `error_log` |
| استایل‌ها لود نمی‌شوند | `BASE_URL` اشتباه در زیرپوشه | `BASE_URL='/نام‌پوشه/'` با اسلش ابتدا و انتها |
| نشست‌ها می‌پرند | مسیر session writeable نیست | `chmod 700` روی مسیر session یا تنظیم `session.save_path` |

## ۷. بک‌اپ و بازیابی

```bash
# بک‌اپ دیتابیس
mysqldump -u DB_USER -p --default-character-set=utf8mb4 DB_NAME > backup_$(date +%F).sql
# بک‌اپ فایل‌های آپلود
tar czf uploads_$(date +%F).tar.gz uploads/
# بازیابی
mysql -u DB_USER -p DB_NAME < backup.sql
tar xzf uploads.tar.gz
```
> توصیه: cron روزانهٔ سمت سرور (در cPanel بخش Cron Jobs) برای هر دو مورد + انتقال به
> مکان خارج از سرور.

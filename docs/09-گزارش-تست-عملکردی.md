### ⚠️ هشدارها (WARN)

#### WARN ۱: `htmlspecialchars` در ۴۱۷ مورد خروجی
**وضعیت:** False positive — بررسی دستی نشان داد که اکثر موارد در توابع helper مثل `nl2br(htmlspecialchars(...))` به‌درستی escape شده‌اند. نمونه‌هایی که به‌عنوان مشکوک شناسایی شدند در واقع متغیرهای امن هستند (مثل ID های عددی `$docId`).

**اقدام توصیه شده:** نیازی به تغییر نیست. برای اطمینان، در نسخه‌های بعدی می‌توان تابع `e()` کمکی اضافه کرد که الزام به escape را ساده‌تر کند.

#### WARN ۲: CSV Injection (Formula Injection) — **اصلاح شد**
**اشکال اولیه:** کلاس `CsvExporter` مقادیری که با کاراکترهای `=`, `+`, `-`, `@`, `\t`, `\r`, `\n` شروع می‌شوند را escape نمی‌کرد. این یک آسیب‌پذیری واقعی (OWASP CSV Injection) است: اگر متقاضی در فیلد متنی مقدار `=cmd|"/c calc"!A1` وارد کند، Excel هنگام باز کردن فایل CSV آن را به‌عنوان فرمول اجرا می‌کند.

**اصلاح انجام‌شده در v0.0.5:**
متد `CsvExporter::sanitizeCell($value)` اضافه شد:
- مقادیر `null` به رشتهٔ خالی
- مقادیر bool به `TRUE`/`FALSE`
- اگر رشته با `=, +, -, @, \t, \r, \n` شروع شود و عدد معتبر نباشد، یک آپوستروف `'` به ابتدا افزوده می‌شود
- اعداد منفی (`-12`) و علمی (`1E5`) معاف می‌شوند

```php
public static function sanitizeCell($value): string
{
    if ($value === null) return '';
    if (is_bool($value)) return $value ? 'TRUE' : 'FALSE';
    $str = (string)$value;
    if ($str !== '' && in_array($str[0], ['=', '+', '-', '@', "\t", "\r", "\n"], true)) {
        if (!is_numeric($str)) {
            $str = "'" . $str;
        }
    }
    return $str;
}
```

تمام فراخوانی‌های `fputcsv` در `CsvExporter::export()` به‌جای نوشتن مستقیم ردیف، آن را از `sanitizeCell` عبور می‌دهند.

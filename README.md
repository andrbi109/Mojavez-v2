# سامانهٔ مدیریت ثبت‌نام و پیگیری صدور مجوز صنایع دستی 🏛️

> **طراحی، توسعه و مدیریت: امین دروگر بزدی** — آیدی `Derogaramin@` در ایتا، روبیکا و بله
>
> **نسخهٔ 0.1.0** — اولین نسخهٔ رسمی (SemVer: هر اصلاح یک واحد به PATCH اضافه می‌شود)

سامانه‌ای تحت وب برای مدیریت کامل فرآیند درخواست مجوز صنایع دستی:
از ثبت‌نام چندمرحله‌ای متقاضی و بارگذاری مدارک، تا پیگیری با کد رهگیری، پنل مدیریت
نقش‌محور، لغو خودکار درخواست‌های منقضی، و گزارش‌گیری Excel/چاپی.

> **فناوری:** PHP 8 خالص (بدون فریم‌ورک و بدون کامپوزر) • معماری MVC دست‌نویس •
> MySQL/MariaDB با PDO و Prepared Statements • Bootstrap 5 RTL (محلی) • فونت وزیرمتن

## 🚀 نصب و راه‌اندازی سریع

### پیش‌نیازها
- PHP **8.0+** با افزونه‌های: `pdo_mysql`, `mbstring`, `fileinfo`, `gd` (اختیاری)
- MySQL 5.7+ یا MariaDB 10.4+ (پشتیبانی JSON و توابع پنجره‌ای)
- Apache با `mod_rewrite` فعال (برای URL تمیز) — یا سرور داخلی PHP برای توسعه

### ۱) دریافت کد
```bash
git clone https://github.com/andrbi109/Mojavez.git
cd Mojavez
```

### ۲) ساخت پایگاه داده
تنها یک فایل اسکیمای یکپارچه اجرا شود (شامل همهٔ جداول، روابط و بذر اولیه):
```bash
mysql -u root -p < database/schema.sql
```
> این فایل با `IF NOT EXISTS` و `ON DUPLICATE KEY UPDATE` طراحی شده است؛ اجرای مجدد
> آن در نصب‌های موجود، داده‌ها را حذف نمی‌کند.
> در XAMPP/Laragon می‌توانید همین فایل را در phpMyAdmin (تب Import) اجرا کنید.

### ۳) پیکربندی
فایل `config/config.php` را ویرایش کنید:
```php
define('APP_DEBUG', true);      // روی سرور واقعی حتماً false
define('DB_HOST', 'localhost');
define('DB_NAME', 'handicraft_license');
define('DB_USER', 'root');
define('DB_PASS', '');
define('BASE_URL', '/');        // در زیرپوشه: مثلاً '/mojavez/'
define('USE_CDN', false);       // true = بارگذاری Bootstrap از CDN
```

### ۴) اجرا — انتخاب پلتفرم

#### الف) سرور داخلی PHP (سریع‌ترین برای توسعه)
```bash
php -S localhost:8000 -t public public/router.php
```

#### ب) ویندوز (XAMPP/Laragon)
```cmd
deploy\windows\install-and-run.bat
```
راهنمای کامل: [`deploy/windows/README.md`](deploy/windows/README.md)

#### ج) لینوکس (Apache + MariaDB)
```bash
sudo bash deploy/linux/install.sh
```
راهنمای کامل: [`deploy/linux/README.md`](deploy/linux/README.md)

#### د) داکر
```bash
cd deploy/docker
cp .env.example .env
docker compose up -d --build
```
راهنمای کامل: [`deploy/docker/README.md`](deploy/docker/README.md)

### ۵) ورود به پنل مدیریت
- آدرس: `http://localhost:8000/admin/login` (یا آدرس پیکربندی‌شده)
- نام کاربری پیش‌فرض: `admin` — رمز عبور: `admin123`
- ⚠️ **پس از اولین ورود، رمز را از بخش «مدیریت کاربران» تغییر دهید.**

### ۶) اجرای آزمون‌ها
```bash
./tests/smoke-test.sh                    # ۱۷۱ آزمون خودکار پوشش‌دهندهٔ گردش‌های اصلی سامانه
python3 tools/static-analysis.py         # ۱۸ تحلیل استاتیک کد
python3 tools/responsive-test.py         # تست واکنش‌گرایی ۸ دستگاه موبایل/تبلت/دسکتاپ
```

## 🔄 گردش وضعیت‌های درخواست

```
پیش‌نویس ← تکمیل اطلاعات ← احراز نشانی ← ثبت درخواست صدور ← بارگذاری مدارک به سازمان ← تأیید اولیه ← صدور مجوز
                                     (مسیر یکطرفه — در هر نقطه امکان تغییر مستقیم به «لغو» وجود دارد)
```

- **لغو خودکار:** اگر بیش از `AUTO_CANCEL_DAYS` روز (پیش‌فرض ۱۴) از رویداد «ثبت درخواست صدور»
  گذشته و وضعیت هنوز به «صدور مجوز» نرسیده باشد → لغو خودکار در هر بازدید از صفحات کلیدی
  (داشبورد مدیر، صفحهٔ پیگیری) یا فراخوانی `GET /check-cancel`.
- **اولویت خودکار:** اگر فاصلهٔ «شروع ثبت‌نام» تا «تکمیل آن» بیش از `PRIORITY_DAYS` روز
  (پیش‌فرض ۱۲) باشد → پرچم ⭐ و نمایش در صدر فهرست‌ها.

## 🔐 خلاصهٔ امنیت

| لایه | اقدام |
|---|---|
| ورودی‌ها | Prepared Statements در همهٔ کوئری‌ها؛ اعتبارسنجی سمت سرور با کلاس `Validator` |
| خروجی‌ها | `htmlspecialchars()` روی همهٔ داده‌های کاربر در نماها |
| فرم‌ها | توکن CSRF در همهٔ فرم‌های POST (شامل AJAX نمایش مدرک) |
| نشست | `session_regenerate_id` پس از ورود، کوکی `HttpOnly` + `SameSite=Lax` + `Secure` روی HTTPS |
| ورود | محدودسازی نرخ: ۵ تلاش ناموفق → قفل ۵ دقیقه‌ای؛ مقایسهٔ زمان‌ثابت رمز |
| آپلود | بررسی پسوند + حجم + **MIME واقعی با finfo**؛ نام‌گذاری تصادفی؛ ذخیره خارج از public؛ `chmod 0640` |
| سرو فایل | فقط از طریق `DocumentController` با بررسی نشست مدیر؛ محافظت Path Traversal با `realpath` |
| خروجی CSV | پیشگیری از Formula Injection (پیشوند `'` برای سلول‌های با شروع `=, +, -, @`) |
| هدرها | `X-Frame-Options`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy` |
| نقش‌ها | گزارش‌ها/ویرایش/کاربران فقط `admin`؛ تغییر وضعیت مطابق `config/workflow.php` |

جزئیات کامل: [`docs/02-امنیت.md`](docs/02-امنیت.md)
